# K7 · RK3576：BSP + 端侧 AI 成长与项目方案

> 目标：6～12 个月内，初步具备「板级 BSP 独立交付 + 端侧视觉 AI」能力，并用 **一个做深的个人项目** 支撑简历（BSP + AI 路线）。  
> 平台：已购 **K7 开发板（RK3576）** + MIPI 摄像头（如 IMX415）+ 家用 HDMI 副屏。  
> 原则：**先系统交付，再外设，再 AI**；深度靠证据，不靠堆芯片型号。

---

## 1. 定位与结论

| 问题 | 结论 |
|------|------|
| 要不要新板做厚 BSP？ | 要。现网验签 3562 很难全流程深入。 |
| 主叙事？ | **自维护板级 BSP + 端侧 RKNN 视觉**，不是云端豆包。 |
| 一个 BSP 通吃 3562/3576/3588？ | **一份镜像不行**；可以做 **多板级工程框架**，每板独立配置。 |
| 只做「能编能烧能亮」够不够看？ | **不够**。必须叠加启动/分区/排障/通路/性能指标。 |
| 简历怎么写？ | **新建一条 K7 项目**；工作 3562 精简保留。 |

---

## 2. 产品形态（端侧 AI 落点）

**本地视觉桌宠 / 桌面感知助手（不上云也能用）**

- 感知：IMX415（或板厂适配的 MIPI CSI）取流 → 人在场 / 简单手势  
- 推理：**板端 NPU（RKNN）**，保留 FPS、占用、延迟数据  
- 交互：HDMI 副屏简单 UI + 可选本地提示音  
- 明确不做主线：云端大模型问答、扫地机、AMP/Hypervisor

端侧 AI 在本项目中是 **核心配菜**；复杂问答若以后加，仅作可选项，不占简历主标题。

---

## 3. 总体架构

```text
[你的板级 BSP 包]
  U-Boot → Kernel(defconfig + DTS) → rootfs → 一键镜像 / 烧录 / 版本号

[感知] MIPI Camera → V4L2 / ISP → RGA → RKNN（检测 / 手势）
[交互] HDMI 显示桌宠 UI；可选 MIC / 喇叭本地提示
[加分] 分区 / 启动耗时 / 最小升级 / Oops-panic 案例文档
```

多 SoC 扩展（以后）：

```text
your-bsp/
  build.sh                      # ./build.sh k7_rk3576
  boards/
    k7_rk3576/                  # 当前主攻
    rk3562_xxx/                 # 以后接入
    rk3588s_xxx/
  common/                       # 共用打包、版本、文档规范
  notes/
  demos/
```

## 4. 分阶段计划

### 阶段 A：官方基线（1～2 周）

**目的：** 板子和 SDK 听你的。

- [ ] SDK 下载完整，`md5` 校验，按说明解压 / `release_sdk.sh`
- [ ] 串口 log 完整保存习惯
- [ ] 官方镜像烧录成功，HDMI 出图，能登录
- [ ] 走通完整编译：U-Boot → Kernel → rootfs → 打包 → 烧自编译镜像
- [ ] 搞清启动顺序、分区表、厂商 `build.sh` 在干什么

**过关：** 不依赖预装包，能从源码打出可启动镜像。

---

### 阶段 B：自己的 BSP 包（3～5 周）

**目的：** 这是「我的板级」，不是跟跑脚本。

- [ ] 独立板级名（如 `k7_rk3576_czj`）
- [ ] 自己的 defconfig + 板级 DTS（可从官方拷贝再改归属）
- [ ] 版本号 / 主机名 / build 时间写入系统
- [ ] 一键脚本：`./build.sh k7` → 镜像 + changelog
- [ ] README：环境、编译、烧录、已知问题

**过关：** 他人按文档能编、能烧。

---

### 阶段 C：做厚（4～8 周，可与 B/D 穿插）

对齐「有深度的 BSP」（面试官/前辈常问的点）：

| 模块 | 交付证据 |
|------|----------|
| 存储 / 分区 | eMMC 分区图；能改大小并说明原因 |
| 启动优化 | 各阶段耗时表；至少一处优化尝试 |
| 网络 | 网口通 + 简单带宽 / 稳定性记录 |
| 升级 | 最小 OTA / AB，或可单独升级 boot/kernel/rootfs 之一 |
| 排障 | **至少 1 个 Oops / panic（或严重 Oops）完整案例** |

**过关：** 能讲 20 分钟「启动 + 分区 + 一次内核问题怎么查」。

---

### 阶段 D：MIPI 摄像头（2～3 周）

- [ ] 使能官方 / 板级 IMX415（或配套 sensor）DTS
- [ ] 稳定 `/dev/video*`，连续预览
- [ ] 摸清分辨率、格式、丢帧
- [ ] 跟调用链：sensor → CSI →（ISP）→ V4L2
- [ ] 记录并修好 1～2 个真实问题（时序 / lane / 格式等）

**说明：** MIPI sensor（IMX415 等）是 **内核驱动 + 设备树**，不是 USB UVC「免驱」。

**过关：** 取流稳定；能讲 probe 失败常见原因。

---

### 阶段 E：端侧 AI（3～5 周）

- [ ] RKNN 工具链：模型 → 量化 → 上板
- [ ] 流水线：取流 → 缩放 → NPU 推理 → 结果
- [ ] 第一模型宜小：人检测或手势（勿一上来重模型）
- [ ] 强制指标：**输入尺寸、FPS、NPU/CPU 占用、延迟、发热**

**过关：** 本地实时检测可演示 + 性能表。

---

### 阶段 F：桌宠产品闭环（2～4 周）

- [ ] 状态机：无人休眠 / 有人唤醒 / 挥手互动
- [ ] HDMI 简单 UI（Qt / LVGL 任选）
- [ ] 开机自启；异常有日志
- [ ] （可选）MIC 本地提示音——非云端对话主线

**过关：** 插电可演示约 3 分钟。

## 5. 深度标准（简历够不够看）

### 不够看（避免停在这里）

- 只会官方 `build.sh`、刷机成功
- DTS 打开节点、摄像头能出图
- 简历全是「熟悉 / 移植 / 调试」无证据

### 够看（同一块 K7，至少拿到 4 项）

1. 自己的板级包（独立配置 + 一键镜像 + 版本）
2. 启动或分区有文档与改动
3. 内核排障案例（Oops / panic）
4. 摄像头链路能讲清 + 修过问题
5. RKNN + 性能数据
6. 可复现交付（README / 开机服务）

> **一个做深的 K7，好过三个浅点亮项目。**

## 8. 简历怎么写

### 8.1 结构

| 条目 | 作用 |
|------|------|
| 工作：科旭 RK3562 智慧能源 | 量产约束、外挂模块；**写短** |
| **个人：K7-RK3576 板级 BSP + 端侧视觉** | 深度主菜；**写厚** |
| 学校 / 实习 | 压缩 |

### 8.2 新项目模板（做成再写，勿提前编造）

**项目名称：** K7-RK3576 板级 BSP 构建与端侧视觉桌宠  
**角色：** 独立负责  
**技术栈：** RK3576、U-Boot/Kernel/rootfs、设备树、V4L2、IMX415、RKNN  

- 基于厂商 SDK 维护板级软件包：统一编译 U-Boot/Kernel/rootfs，输出可烧录镜像与版本管理  
- 完成板级设备树与启动配置；梳理 eMMC 分区与启动耗时，具备启动参数与分区调整能力  
- 适配 MIPI CSI IMX415，打通 sensor→CSI→V4L2 取流，保障连续预览稳定  
- 部署 RKNN 端侧检测，完成取流–缩放–推理流水线，并统计 FPS / NPU 占用 / 延迟  
- 实现本地视觉桌宠状态机，业务与板级镜像一体化交付  
- （有则写）定位并修复内核 Oops/panic 或驱动问题，完成调用栈分析与回归验证  

### 8.3 工作项目精简方向

保留：验签内核、DTB 单独升级、外挂模块 vermagic/shim、音视频通路。  
压缩：698/376 规约、台体、业务细节。

### 8.4 何时写入简历

| 进度 | 是否上简历 |
|------|------------|
| 仅官方镜像 | 否或仅笔记 |
| 自编译镜像 + 板级目录 | 可写 BSP 前半 |
| IMX415 稳定 + RKNN 出数 | 写成完整 BSP+AI |
